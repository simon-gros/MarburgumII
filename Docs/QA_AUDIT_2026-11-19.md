# Quality assurance audit — 19 November 2026

**Audited:** `main` at [`55f8236`](https://github.com/simon-gros/MarburgumII/commit/55f8236) (ADR-068). Corrections are on branch `qa/fixes-2026-11-19`, from `2316b91` (on `main`) to `9e6dbfc` and the documentation commit after it. Engine: Unreal Engine 5.8.3 on Linux. Method: six read-only subsystem reviews (server authority and persistence, accounts and admission, character gameplay, UI and first launch, living world and performance, build/tests/CI), read against the code and the UE 5.8.3 engine source, and a second security review of the account system against the fixes of the first (`Saved/QA/reviews/accounts-rereview-2026-11-19.md` in the QA worktree). Every correction was then reproduced or measured where it could be, built, and run through Unreal automation and the affected smokes. **No personal owner playtest is part of this audit.** "Editor" smokes run uncooked `UnrealEditor -server/-game` processes; "staged" smokes run the packaged Linux client and server.

## Assessment

The authoritative core is sound. Server-decided movement, receipts and replay protection, a durable store that never overwrites an unreadable file, ticketed admission and server-only rules all held up under review. Nothing was found that corrupts saved state in normal operation. The defects found are at the edges:

- **Trust gaps.** Development switches were honoured for signed-in players, test RPCs had no rate limit, refusals multiplied reliable traffic, and client RPCs could mint permanent engine names. The account service could be exhausted by password checks, sessions or silent connections, and HTTPS to it did not insist on a checked certificate. One trust gap is open: admission tickets are not bound to the server they were issued for (AR1, proposal).
- **Packaging.** A clean checkout of `main` did not compile. Assets loaded by path were never cooked. Smoke and playtest evidence could not tell a stale build from a current one.
- **Interrupted states.** These cover being seated, being down, typing in chat, a dropped connection, and two servers sharing one store.
- **Player-facing polish.** Screens ran off the screen, there was no Escape or exit, developer text appeared on player screens, and story lines were pushed out of the notification feed.
- **Per-frame and replication costs.** The living world added the most of these.

The game is **not production-ready**. The open items below are real, the street smoke fails on `main`, the Escape menu awaits the owner's approval, and no package of these fixes has been owner-tested.

## Principal obstacles to professional quality

1. **Evidence freshness.** Before this audit, nothing tied a smoke or playtest to the build it ran. The build stamp and the playtest seal now do. CI still never compiles C++ or runs UE tests, so a broken unity blob reached `main`.
2. **Editor-only qualification.** Most recent features were proved in editor mode only, and packaging dropped three of them silently. Each feature needs a staged smoke before it is called done.
3. **One-player assumptions in the living world.** Street population, zones and the walk graph were designed and tested with one player. W1, W5 and W6 need multi-client smokes.
4. **No owner-approved first-launch path.** Escape, exit, scaling and the account screens at other resolutions remain unapproved.
5. **The account service is a single process with one lock and one JSON file.** Two reviews in one day each found ways to stall the game server's redeem through it. The bounds added today hold for a small community; a public launch needs AR1, AR3b and AR7 and a deployment review.
6. **Fixes verified by the smokes that exist.** Several corrections (G4, G6, U5, U7, U10) have no smoke that drives the exact case; they are verified by build, automation and code reading only, and are listed as such.

## Recommendations

- Merge `qa/fixes-2026-11-19` after review. The head of every round was built with strict unity and kept automation green; commits inside a round were not built one by one.
- Decide AR1 (tickets bound to their server, per-server keys) before any server other than a development one accepts accounts.
- Make a staged smoke matrix plus `build-stamp.sh check` the definition of done for a feature, and add a self-hosted CI job for the UE build and automation.
- Hand W12, W1, W5 and W6 to the street work after ADR-069 lands. Rerun this audit's living-world review on the result.
- Run `scripts/ui-capture-linux.sh` on the new UI (UX1) and schedule an owner playtest of the Escape menu, the scrolling screens and the first-launch path.
