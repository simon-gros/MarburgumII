## Executive result

The focus shifted from a single riverside prototype to a more ambitious **integrated nine-window neighborhood** with actual surveyed ground and street collision, server-run unarmed fighting and responsive ambient pedestrians. There are now cross-system interactions: punches create street incidents, pedestrians flee/watch/fight back, and moving cars can knock people down while others dodge or react. Rigged animation corrections make the **drawn** swim, door and fight poses follow their clips rather than having the mannequin's foot IK hold the legs upright.

Each lane has different evidence quality. **Do not equate** a passing editor smoke, earlier packaged combat smoke, compiled client/server source, the current nine-window map, and an accepted public multiplayer showcase.

## Reordered work and concrete qualification gates

**P0-A — Latest source and cooked-asset integrity.** Rebuild/repackage a clean revision including nine-window ground, facades, all swim/vehicle/combat animation regenerations, new street walk graph and loose staged files. Seal their hashes and inputs with [playtest freshness](PLAYTEST_FRESHNESS.md), verify Editor/Client/Server map paths, load and module boundaries. Run all existing interaction/chat/Lent/condition/swim/vehicle/combat/street smoke tests, explicitly mark whether each used `staged` or `editor`, and perform one real multi-client packaged integrated run on the expanded level. New map changes must not silently invalidate earlier one-window captures.

**P0-B — World collision and performance.** Verify boundaries between all nine windows, crossing and kerb transitions, terrain under bridges, roof/building collision, swim volume seams, vehicle navigation, graph connectivity and disappearing/reappearing pedestrians. Record cold load, CPU/GPU frame-time tails, VRAM, draw calls, navigation/physics and dedicated-server cost while traveling between windows. Evaluate **streaming/World Partition** only from evidence; do not assume the expanded single level already streams. Resolve/report deep hollow decisions instead of silently filling historically meaningful sites.

**P0-C — Multi-client authority, population and combat.** Add staged two/three-client pedestrian tests: no duplicates or out-of-view pop-in anomalies, per-player spawn/cull boundaries, remote-visible fight/run-over/dodge results, observer privacy, target ownership, two-player interactions, reconnect/server restart, incident spread limits, no accidental PvP, no impossible car hits, and NPC reset/body despawn. Stress-test 1/2/4/8 clients and controlled pedestrian counts before contemplating shard targets. Preserve the game's explicit **no wanted/police pursuit** rule.

**P0-D — Public-entry and graphical acceptance.** UI-02A authenticated email→credentials→First/Last/model→server-owned character admission still blocks the *public* Stage 1. Finish Skills/Settings, focus priorities for chat/drive/interact/jab/guard, combat/incident feedback hierarchy, condition/down/guard stamina and prompt states, resolution/controller/scale tests and a compelling 1440p/4K honest capture. Owner must personally test road walking, fight, swim, driving, crowd responses and traversing all eight new neighboring areas on the fresh build.

**P1 — Close an existing complete gameplay loop.** Implement real fishing/caught item and `lent_first_catch` completion with server-owned validated transactions; keep it ahead of speculative city-size expansion. After that, add simulation breadth incrementally: simple 1990s everyday pedestrian routines and believable sound/crowds, route/link repairs, NPC awareness, road furnishings, rights-cleared vehicle/swim audio, and eventually car persistence/ownership/fuel/traffic/damage. Combat consequences must be designed separately from the **explicitly excluded** wanted/police-chase mechanics.

## Proof and acceptance

Use four independent statuses: `implemented`, `automated_tested`, `fresh_build_verified`, `owner_approved`. ADR “accepted” refers to design/code decision; it does not override the project owner's personal in-game sign-off (ADR-008). Every showcase claim must state tested source commit, UE 5.8.3 version, map/window set, source and cooked assets, client/server process modes, regression logs, screenshot/video, remaining omissions, and explicit owner decision. The **latest nine-window change is not automatically accepted as a production world simply because its four editor smoke tests passed**.
